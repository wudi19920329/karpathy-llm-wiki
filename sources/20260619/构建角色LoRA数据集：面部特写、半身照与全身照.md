# 构建 Flux.1 角色 LoRA 数据集：面部特写、半身照与全身照——完整工作流程

## 摘要

- **按优先级顺序构建数据集——先面部特写，其次半身照，最后全身照——但将重复次数权重设为约 1:2:3（特写:中景:全身）**，使约 50% 的训练图像视图来自全身照。面部训练快且准确，而全身照中的小脸训练很慢，这是"全身照中脸变形"问题的首要原因。总计：目标约 20–40 张高质量 1024px 图像。
- **Flux.1 所需图像少于 SD1.5/SDXL，但对标注文本的依赖更重。** 使用自然语言标注（JoyCaption/Florence-2/BLIP），在 1024 分辨率下以 512/768/1024 桶训练，秩 16–32（最大面部保真度用 64），学习率 1e-4（AdamW8bit），约 1000–2000 步，每 250–500 步保存一次检查点以挑选最佳结果。
- **最常见的错误是构图比例失衡**（全是自拍 → 无法做全身；全是全身 → 脸模糊）。通过 Kohya 重复文件夹方法、多分辨率桶，以及涵盖三种景别的固定测试提示集来修复。

## 核心要点

1. **顺序/优先级：** 先收集面部特写（锚定身份、训练最快），其次半身照，最后全身照。全身照最难做好、最容易漂移，因此需要最多图像和/或重复次数。
2. **比例：** Civitai《训练技巧：平衡重复次数》的作者推荐以重复次数加权的 **1:2:3 规则**（中景重复次数 = 特写的 2 倍，全身重复次数 = 特写的 3 倍）——这意味着约 50% 的训练图像视图来自全身照——因为全身构图中脸只占画面极小部分，训练很慢。原始图像数量可以更均衡；不平衡是通过重复次数来施加的。
3. **质量：** 1024×1024 或更大，优先使用无损格式（PNG），清晰、无水印/压缩失真、画面中无其他角色。现代建议倾向于使用*多样化*的背景（而非纯色），以使模型将注意力隔离在主体上。
4. **标注：** 自然语言是 Flux 的首选；标签（WD14）是 SD1.5/SDXL 的首选。**将你不希望烘焙进触发词的所有内容都标注出来。**
5. **数据集大小：** 最少约 10 张；角色 LoRA 理想为 20–40 张。超过约 40–50 张而没有增加多样性会导致过拟合。
6. **预处理：** 人脸检测与裁剪、去重、质量筛选、分桶。
7. **训练参数：** 秩 16–32，alpha = dim，学习率 1e-4（AdamW8bit），1000–2000 步，1024 分辨率配多桶，批次大小 1，bf16。
8. **常见错误：** 构图比例失衡、背景全部为纯色、重复的服装/背景、过度标注面部特征、图像过多、训练过长。
9. **Flux 与 SD 的差异：** flow-matching 架构、学习率低于 SDXL 的 1e-3、使用自然语言标注、需要更高 VRAM、所需图像更少、使用 T5 文本编码器。
10. **工具：** Kohya sd-scripts/GUI、FluxGym、Ostris AI-Toolkit、SimpleTuner，以及数据集工具（FiftyOne、LoRA-Dataset-Automaker、Birme、Florence-2/JoyCaption/BLIP）。

## 详细说明

### 1. 三种景别的推荐顺序与优先级

社区共识的工作流程是按以下顺序收集和排列优先级：

**面部特写 → 半身照 → 全身立绘**

其原理在于*训练损失的分布方式*。正如 Civitai《训练技巧：平衡重复次数》文章所解释的，在全身照中"脸只占图像（因而也只占引导训练的损失）的很小一部分"，因此脸在那里训练很慢。而特写则相反——用该作者的话说——"似乎训练得非常快且准确。这并不奇怪，因为脸几乎占据了完整的图像。关于脸的知识也会从中景照片迁移过来。这就是为什么我们平均每 6 张图像中只训练一张特写就够了。"

这就是为什么 kohya-ss/sd-scripts Issue #1916——"无法用人脸 LoRA 生成全身"——如此普遍。报告者写道："我用 flux 用一些人脸图像训练了一个 LoRA 模型……生成全身人物时，LoRA 模型的脸会变化。"仅有人脸的数据集会产生一个在全身输出时脸部漂移的 LoRA，因为模型从未见过以全身构图中出现的小尺寸渲染的脸。

因此优先级逻辑是：
- **先面部** —— 是身份的锚点，最容易获取，学习最快最准确，从一张高分辨率照片裁剪可以生成多张特写。
- **其次半身** —— 将面部保真度桥接到身体/服装背景；脸仍然足够大，可以强化身份。
- **最后是全身照，且最难** —— 姿势、比例和立绘风格全身图所必需，但小脸意味着必须通过更多图像、更高重复次数，和/或在更高分辨率下训练来补偿，以使脸部有足够的像素进行学习。

### 2. 各景别的数量与比例

有两个层面：**原始图像数量**和**重复次数权重**。

**原始数量（角色 LoRA，约 20–40 张）：** Civitai Flux 指南推荐的平衡"禅宗原则"数据集包含"几张全身照、几张肖像视图、几张牛仔构图和几张面部特写"，以及正面/侧面/背面角度。SeaArt 的角色数据集指南给出了一个说明性的 30 张图像分解（约 12 张肖像/特写，6 张上身，8 张全身，加上姿势/背景多样性），并有一条重要规则：任何单一的非身份属性（特定背景、特定服装）在**最多 3–6 张**图像中出现。（将确切的 12/6/8 拆分视为说明性示例，而非权威规定。）

**重复次数权重（Flux/SD 的关键见解）：** Civitai《平衡重复次数》方法按*脸的大小*而非全身是否可见对图像进行分类：
- **特写** = 脸占画面约一半或更多
- **中景/半身** = 上半身，脸仍然较大
- **全身** = "当膝盖进入画面时，脸非常小"，算作全身

推荐的权重是作者的 **"1/2/3 规则"：中景重复次数 = 特写的 2 倍，全身重复次数 = 特写的 3 倍**（= 特写 + 中景）。他的明确警告："按照 1/2/3 比例，50% 的训练图像来自全身文件夹。如果你发现身体需要非常高的重复次数，你真的应该添加更多（且多样化的）图像。"这一反直觉地将最难的类别放在前面，因为它学习最慢。他还警告说"完全平衡的特写/中景/全身照不会产生好的训练结果"——即使权重下，特写生成的效果会有"夸张特征（看起来很奇怪、更老）"而远处的脸仍然不对。

Kohya 中的实际实现：使用单独的编号文件夹，例如 `3_closeup`、`6_midshot`、`9_fullbody`（下划线前的数字是重复次数），或使用 Kohya 内置的"Dreambooth/LoRA 数据集平衡"选项卡。如果没有好的全身照，解决方法是*添加更多多样化的全身图像*，而不仅仅是增加重复次数（那样会过拟合姿势/服装）。

一个更简单、同样有效的启发式方法来自 Kohya MimicPC 指南："原始数量上，突出脸部的图像比例相对较大，全身图像比例较小——然后通过重复次数重新平衡，使训练不足的身体类别获得足够的权重。"

### 3. 图像质量要求

- **分辨率：** 理想为 1024×1024（约 100 万像素）或更高；加载器会缩小，所以高分辨率源图像在缩放时压缩伪影会被清除。512 可以接受但较差。至少包含一些接近 1024 原始分辨率的图像。
- **裁剪：** 裁剪到与训练桶匹配的安全宽高比（1:1 是最安全的——"完美正方形像素最多"）。一张高分辨率全身图可以裁剪成牛仔构图、头肩照和面部特写，以及标志性物品的细节裁剪（武器、吊坠、皮带扣）。
- **背景：** 现代指导推翻了旧的"纯色背景"规则——*多样化*背景有助于模型将注意力隔离在主体上，而不是记忆环境。但要避免有其他角色或干扰元素的繁杂背景。关键是，不要在多张图像中重复相同的背景，否则它会烘焙进 LoRA。
- **光照：** 变化光照（自然光、棚拍、柔光、戏剧性光）以使 LoRA 泛化；所有图像使用统一光照会将该光照烘焙进去。避免模糊、光线差或像素化的图像。
- **格式：** 优先使用无损格式（PNG/TIFF）而非 JPEG。无水印、无 logo、无文字叠加。

### 4. Flux.1 的标注/说明文字策略

这是 Flux 与 SD1.5/SDXL 差异最大的地方。

- **Flux 使用自然语言标注。** Civitai Education 的训练文档指出，"自然语言标注是 Flux LoRA 训练的首选方法"（通过 JoyCaption），而基于标签的 WD Tagger 1.4 输出"是 SD1.5 和 SDXL 类 LoRA 标注的首选方法"。Flux 使用 T5 文本编码器，依赖完整句子。
- **两者兼得：** 一位有 40 个 LoRA 经验的从业者建议"同时使用 WD14 和 LLM 自然语言标注，以确保 CLIP 和 T5 信息都存在"——Flux 同时具有 CLIP 和 T5 编码器。
- **黄金法则——标注你希望可变的内容，省略你希望烘焙进触发词的内容。** "就 LoRA 而言，触发词就是你没有标注的东西。"对于角色：标注服装、姿势、背景、表情、相机构图（例如"近景肖像"、"全身照"）和风格（"照片"、"动漫插画"）。**不要**标注不可互换的身份特征（脸型、眼睛颜色、标志性发型），如果你想让它们与角色绑定。
- **按景别明确标注构图。** 因为你在混合特写/半身/全身，在每个标注中包含景别（"特写"、"半身照"、"全身站立"），使构图成为可控的轴，而不是与身份纠缠在一起。
- **触发词：** 一个短小、罕见的非词典词（例如 `eksray`、`p3rs0n`、`ch3rrybl0nde`）加上一个类别词（女性/男性/角色）。将其放在标注和提示词的开头。
- **自动标注工具：** Florence-2（FluxGym 默认）、JoyCaption（Civitai）、BLIP/BLIP2，或 LLM（Gemini/GPT-4V）用于最高质量的结构化标注。始终**人工审核**自动标注——从业者指出即使一张标注错误的图像也会损害 LoRA。

### 5. 数据集大小建议

- **绝对最低：** 约 10 张（Flux 可以从极少数图像做出可用的角色 LoRA，甚至可以用注意力掩码技巧从 1 张开始）。Apatero 的最佳实践指南引用了"根据 Finetuners.ai 的研究，十张图像是灵活且稳定模型的最低要求"。
- **理想：** 角色 20–40 张。多位独立从业者汇聚于此——25–27 张足以训练出"与真实面部特征非常相近"的个人 LoRA，Apatero 注意到 SD 1.5"需要 70-200 张，而 Flux 需要 25-30 张"。
- **上限/过拟合：** 在没有相应多样性的情况下超过约 40–50 张会适得其反——一位训练者发现"当我包含 40–50 张图像时，LoRA 似乎失去了对主体的聚焦"。质量和多样性胜过原始数量。（云平台如 fal 允许 20–1000 张，但该范围适用于大型风格/身份任务，而非典型角色 LoRA。）

### 6. 预处理步骤

1. **收集与去重。** 删除完全重复和近似重复的图像（近重复会放大某些姿势/角度并导致过拟合）。工具使用感知哈希或嵌入余弦相似度；FiftyOne + CLIP 嵌入是常见的筛选栈。
2. **人脸检测/方向校正。** 检测人脸，自动旋转方向错误的图像，并验证身份照片中有可用的人脸。FaceChain 等流程链接旋转校正 + 面部提取；LoRA-Dataset-Automaker notebook 使用 YOLO 动漫/写实人脸检测器以及与参考人脸的相似度筛选。
3. **质量筛选。** 丢弃模糊、低分辨率、有水印、严重压缩或有多个角色的图像。
4. **按脸的大小分类**到特写/中景/全身文件夹（这驱动你的重复次数权重）。
5. **裁剪与分桶。** 裁剪到安全宽高比；让训练器按分辨率分桶。从高分辨率图像生成额外裁剪以填充薄弱类别。
6. **标注与审核。**
7. **（可选）增强**薄弱类别——水平翻转对某些风格可以，但对不对称脸部存疑；或使用图像编辑模型（Flux Kontext、Qwen-Image-Edit）从干净的身份源合成额外角度。

### 7. Flux.1 特定训练参数

**角色**（而非风格）Flux.1-dev LoRA 的共识值：

| 参数 | 推荐值 | 备注 |
|---|---|---|
| **学习率（AdamW8bit）** | **1e-4**（范围 5e-5–2e-4） | Ostris CLI/notebook 示例默认值。Ostris *Gradio UI* 默认值（flux_train_ui.py）为 4e-4（激进端）。**避免使用 1e-3——那是 SDXL 的约定。** |
| **学习率（Prodigy）** | **1.0**（自动调整） | 如果不想猜测时使用；SimpleTuner 默认值 |
| **学习率（Adafactor）** | 自调整 | Kohya fused-backward-pass 低 VRAM 所需 |
| **网络秩/dim** | **16–32**（Ostris 默认 16） | 最大面部保真度用 64（Apatero）；128 仅用于高细节/大文件 |
| **网络 alpha** | **= dim**（Ostris） | 旧 SD 约定使用 alpha = dim/2；alpha 缩放有效学习率 |
| **总步数** | **1000–2000**（约 40 步/图像） | Ostris notebook 默认 2000（"500-4000 是好范围"）；Flux 收敛快（可能 500–1000 步）。每 250–500 步保存一次并挑选最佳 |
| **分辨率** | **1024** 主要，桶 **[512,768,1024]** | Ostris 配置注释："flux 喜欢多分辨率" |
| **优化器** | **AdamW8bit** | Adafactor（低 VRAM）、Prodigy（自动学习率）可作为替代 |
| **学习率调度器** | constant / constant_with_warmup | cosine_with_restarts 也常用；短预热 |
| **批次大小** | 1 | （VRAM 足够时用 2–4；将收敛步数减半） |
| **精度** | bf16，梯度检查点 | |
| **其他** | EMA 开启（decay 0.99），noise_scheduler flowmatch，guidance_scale 1.0，caption dropout 约 0.05 | |
| **VRAM** | 最低 16GB，24GB 舒适 | |

**重要说明（SECourses）：** 引用的学习率"完全没有意义，除非同时提供 alpha 和秩"，因为有效学习率 = 学习率 × (alpha/秩)。始终同时报告三者。

**专门针对全身照中脸的问题：** kohya-ss Issue #1916 的修复方法是"添加与期望输出大小相同的人脸图像"——即包含脸很小的全身照，或使用多分辨率桶以使模型在小尺寸下看到脸。这正是 [512,768,1024] 桶集和全身加权重复比例重要的原因。注意：没有来源提供受控基准证明多桶*特别*能修复全身人脸漂移；这是强有力的社区推理，而非测量结果。

### 8. 应避免的常见错误

- **构图比例失衡。** 全是近景自拍 → 模型"难以做全身"；全是全身 → 脸永远不清晰。这是面部+半身+全身数据集的主要失败模式。
- **天真地"完美"平衡。** 相等的特写/中景/全身重复次数会产生夸张的特写特征和薄弱的远距离脸——将权重向全身倾斜。
- **在大多数图像中重复相同的服装/背景/光照** → 烘焙进 LoRA（"服装渗透"、强制背景）。除身份外将一切都变化；任何单一属性上限为 3–6 张图像。
- **过度标注身份特征**（标注你想要锁定的角色脸/发型）→ 触发词无法捕捉它们。
- **图像过多/训练过长** → 过拟合、塑料皮肤、姿势锁定。超过约 40 张图像时增加多样性，而不仅仅是数量。
- **将 SD 配置复制到 Flux** —— 错误的学习率（1e-3）、标签式标注、步数不足。
- **JPEG/有水印/多角色源图像。**
- **不保存中间检查点** —— 你无法恢复最佳 epoch。

### 9. Flux.1 与 SD1.5/SDXL 的特定差异

- **架构：** Flux 使用 **flow-matching**（整流流），而非经典扩散——设置不可转移。使用 noise_scheduler "flowmatch"，训练时 guidance_scale 1.0。
- **学习率：** 远低于 SDXL——1e-4 vs SDXL 常用的 1e-3；复制 SDXL 的学习率"会产生垃圾"。
- **标注：** 自然语言（T5）胜于 booru 标签；Flux"在训练和推理中更重度使用标注信息"。
- **更少图像：** Flux 每张图像提取更多信息——20–40 张 vs SD1.5 通常需要的 70–200 张。
- **更多 VRAM：** 最低 16GB / 24GB 舒适；SD1.5 需求少得多。使用 FP8/量化和梯度检查点。
- **秩：** 较高的秩在 Flux 上往往比 SD 效果更好；但角色 LoRA 在 16–32 下仍然表现良好。
- **两个文本编码器：** CLIP-L + T5-XXL —— 同时使用标签和自然语言信息标注可能有帮助。
- **分辨率：** Flux 原生受益于多分辨率桶（桶步长 32 vs SD 的 16）。
- **收敛：** 更快——500–1500 步即可使用，而 SDXL 可能需要 3000–5000 步；过拟合（而非训练不足）是主要风险。

### 10. 数据集准备和训练的推荐工具

**训练框架：**
- **Kohya sd-scripts**（+ bmaltais GUI）—— 标准选择；支持 SD1.5/SDXL/Flux，重复文件夹平衡，LoRA+。
- **FluxGym** —— 适合初学者的 Web UI，封装 AI-Toolkit 接口 + Kohya 后端；运行于 12–24GB VRAM；内置 Florence-2 自动标注。
- **Ostris AI-Toolkit** —— 目前最流行的 Flux 训练器之一；简洁配置、Gradio UI、多分辨率桶、EMA；支持 Flux.1/Flux.2/Qwen/SDXL。
- **SimpleTuner** —— 对配合 Prodigy/自适应优化器的 Flux 很强；适合较大数据集。
- **ComfyUI Flux Trainer** —— 基于节点；集成 BLIP 标注。
- **云端：** RunPod、Replicate、fal、MimicPC、RunDiffusion（预配置的 Kohya/FluxGym 模板）。

**数据集准备：**
- **标注：** Florence-2、JoyCaption、BLIP/BLIP2、WD14 Tagger v3（用于标签），或 LLM（Gemini/GPT-4V）用于结构化自然语言标注。
- **筛选/去重：** FiftyOne（+ CLIP 嵌入）、LoRA-Dataset-Automaker（人脸检测 + 相似度）、感知哈希去重。
- **裁剪/缩放：** Birme（批量裁剪到 1024），或训练器自带的分桶功能。
- **人脸检测：** YOLO 人脸模型（写实和动漫变体）、InsightFace 用于身份相似度筛选。
- **增强：** 基于 Albumentations 的工具；Flux Kontext / Qwen-Image-Edit 用于合成缺失角度。

## 建议

**阶段 1 — 规划与收集（目标 20–40 张图像）**
1. 确定触发词和类别（例如 `ch4rname woman`）。
2. 先收集面部特写（≥6–10 张），其次半身照（≥6 张），再次全身照（≥8 张）。优先获取全身照，因为最难。如果全身照不足，*找到或生成更多*——从全身照裁剪出特写没有问题，反过来不行（裁剪特写不能给你真正的全身视角）。
3. 变化背景、光照、姿势、表情和角度（正面/¾/侧面/背面）。如果服装是角色的一部分则保持一致；否则变化并标注。

**阶段 2 — 预处理**
4. 去重、质量筛选、自动旋转、确认人脸。
5. 按*脸的大小*分类到 `closeup` / `mid` / `fullbody` 文件夹。
6. 裁剪到 1:1 或安全宽高比；确保几张图像约为 1024px。
7. 自动标注（Florence-2/JoyCaption）→ 人工编辑：添加触发词 + 景别 + 可变属性；删除你想要锁定的身份描述词。

**阶段 3 — 配置训练（Flux.1-dev 角色基准线）**
8. Kohya/FluxGym/AI-Toolkit；秩 16–32（面部保真度最重要时用 64），alpha = dim，学习率 1e-4 AdamW8bit，1024 分辨率配 [512,768,1024] 桶，批次 1，bf16，EMA 开启。
9. 将重复次数设为约 1:2:3 特写:中景:全身比例（例如文件夹 `3_closeup`、`6_mid`、`9_fullbody` 以实现约 50% 全身权重——根据你的数量调整）。目标约 1000–2000 总步数（约 40 步/图像）。
10. 每 250–500 步保存一个检查点。

**阶段 4 — 评估与迭代**
11. 构建一个**固定测试提示集**，涵盖相同表情的特写、半身和全身。比较检查点；挑选在*所有三种*构图中脸部一致的那个。
12. **决策阈值：**
   - 仅在全身照中脸部漂移/变化 → 添加更多全身图像和/或提高全身重复次数；确认多分辨率桶已开启；在 1024 下训练。
   - 特写看起来"过熟"/变老 → 降低特写重复次数或总步数。
   - 服装/背景渗入每次生成 → 该属性重复过多；多样化并标注它。
   - 各处肖像感都弱 → 增加步数/秩，或提高图像质量；检查标注中是否描述了脸部。
   - 皮肤塑料感/过平滑 → 减少步数，在推理时添加纹理提示词。
13. 一旦最佳检查点在 LoRA 强度 0.7–1.0 下的完整测试提示集中保持一致性，即可投入使用。

## 注意事项

- **数值是起点，不是定律。** 最优步数、秩和比例取决于图像数量、质量、优化器和主体。重复比例（1:2:3）和步数规则（约 40/图像）是广泛使用的启发式方法，而非经过基准测试的常数。
- **学习率数值在不同情况下不可直接移植**，除非同时说明秩和 alpha（有效学习率 = 学习率 × alpha/秩）。谨慎对待任何单独引用的学习率，并注意 Ostris 默认值的冲突（CLI 1e-4 vs Gradio UI 4e-4——两者都是"官方"）。
- **"多桶修复全身人脸漂移"的说法是社区推理**，由架构和 kohya-ss 修复方法（"在期望输出大小下添加人脸图像"）支持，但没有受控研究证明。
- **来源混合：** 大部分最佳实践细节来自从业者博客、Civitai 指南和工具文档，而非同行评审的工作；视为经过充分测试的社区共识，并在你自己的主体上验证。
- **许可证：** Flux.1-dev 是非商业的；在其上训练的 LoRA 继承该限制。在商业使用前请查看当前许可证条款。
- **快速发展的领域：** Flux.2（dev/klein）和其他 2026 年模型有不同的 VRAM 和秩需求（Flux.2-dev 可能需要 80GB+ VRAM）；本指南专门针对 Flux.1-dev。
