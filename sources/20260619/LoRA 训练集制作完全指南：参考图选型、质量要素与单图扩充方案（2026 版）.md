# LoRA 训练集制作完全指南：参考图选型、质量要素与单图扩充方案（2026 版）

## TL;DR
- **第一张/锚定参考图应选「面部特写或胸像（头+肩）」**——身份相似度是 LoRA 最难学、最需要像素的部分；但绝不能只用特写，必须搭配半身与全身图，否则全身出图会"崩"。社区主流配比为 **全身:半身:特写 = 1:1:1（上限 1:1:2）**，或特写权重最高的 4:3:1，特写中人脸应占画面 40–60%。
- **质量要素核心**：SD1.5 用 512–768px、SDXL/Flux 用 1024px；主体清晰无遮挡、人脸精修是真人 LoRA 的命门、手部精修必要性较低；构图避免主体过远（远景像素浪费）；保持"训练目标一致、其余（光影/背景/角度/服装）多样"的黄金原则。背景处理出现了范式转变——旧观念主张纯色背景，2025 年后主流转向"多样背景以教会模型分离主体"。
- **单张/少量图扩充训练集的最佳现代方案**：首选 **Flux Kontext 或 Qwen-Image-Edit-2509/2511**（基于参考图编辑、身份一致性最强），用 ComfyUI 工作流批量生成 30–60 张多角度/多姿势变体，人工挑选后再用 FluxGym / AI-Toolkit / Kohya 训练。IP-Adapter/InstantID/Reference-only 是更早期方案，可用但各有局限。

## Key Findings

1. **锚定图类型**：权威指南（HuggingFace Diffusers 官方训练博客、Civitai 高赞教程）一致认为应以面部/胸像特写作为身份锚点，理由是"特写照对最终真实感至关重要"（HuggingFace 官方 SDXL LoRA 博客原文："Close-up photos are important to achieve realism, however good full-body shots should also be included to improve the ability to generalize to different poses/compositions."），且应"避免离主体太远的照片，因为大部分像素与要学习的概念无关"。但必须补充全身图以提升对不同姿势/构图的泛化。

2. **特写 vs 全身的权衡是核心矛盾**：纯特写 → 全身出图畸形；纯全身 → 人脸像素太少学不到细节。解决方案是"控制性多样"——按比例混合三种景别，并对特写文件夹给更高 repeat 权重（知乎实测：提高肖像文件夹 repeat 反而学得更快）。

3. **具体配比**：业界数字集中在"特写最多、半身次之、全身最少（约10–30%）"。常见明确配比：1:1:1（上限1:1:2）、4:3:1（32特写+24半身+8全身）；人脸应占特写画面 40–60%（一说 60–80%）。

4. **分辨率**：SD1.5 用 512×512/512×768/768×512；高显存或精细 LoRA 用 768×768；SDXL、Flux、SD3.5 用 1024×1024。原图尽量 1024px 以上，可缩小不可放大。所有边须为 64 的倍数（或开启 ARB/分桶 bucketing 免裁剪）。

5. **数量**：人物/角色类 15–30 张是社区公认甜点区（20–25 最佳），具象类约 20 张，风格类 50–200 张。"图多≠更好"，过多同质化会过拟合、权重偏移。

6. **背景范式转变**：旧主流是纯色/去背景；2025 年后 RunDiffusion 等明确指出"现代 LoRA 训练受益于环境多样性——背景变化教会模型分离主体，而非记住固定环境"。但纯黑/纯白背景训练易被模型"学进去"，需谨慎。

7. **面部精修 vs 手部精修**：人脸精修对真人 LoRA 极重要（真人参数要求比动漫高 20–70%）；手部精修在数据集层面必要性低——主流做法是出图后用 ADetailer/FaceDetailer 二次修复手与脸，而非在训练集上死磕。

8. **单图扩充工具代际**：Reference-only ControlNet（最早，多角度一致性差）→ IP-Adapter/IP-Adapter-FaceID（CLIP 嵌入，相似度中等，会泄漏风格）→ InstantID（单图零训练，正面脸最佳，全身弱）→ **Flux Kontext / Qwen-Image-Edit（当前最强，基于参考图编辑而非从头生成，身份一致性显著领先）**。

## Details

### 一、第一张参考图（锚定图/触发图）选型

**结论先行：选面部特写或胸像（头+肩）作为锚定图，但全套数据集必须三种景别混合。**

LoRA 训练中"第一张图"有两层含义需区分：
- **数据集锚定图（identity anchor）**：你用来定义角色长相、并据此扩充整个数据集的那张基准图。**应选清晰、正面或近正面、表情中性、无遮挡的面部/胸像特写**。Civitai 高赞教程《How to Create a Perfect Dataset for a Character LoRA》（作者 rolenzio）明确写道："关键是拿到一张胸像或脸部的图——它不需要是照片级真实的。"该作者进一步建议生成起始图用竖构图 1024×1536、含上半身，"训练时一致性更好"。
- **caption 中的"触发词/激活标签"**：这是另一回事——指 .txt 标注文件第一个 token 的唯一触发词（如 sks、ohwx、plu），用于激活 LoRA。知乎/Kohya 教程指出 caption 前 4 个 token 会被保留不打乱，触发词应放首位。

**三种景别的优缺点：**

| 景别 | 优点 | 缺点 | 对训练效果影响 |
|---|---|---|---|
| **面部/头部特写** | 人脸像素最多，身份相似度最高；真实感最关键 | 泛化差，全身出图易畸形；构图单一 | 决定"像不像"的上限；HF 官方："特写照对最终真实感至关重要" |
| **半身立绘（腰/胸以上）** | 兼顾脸部细节与姿态/肩颈/服装上下文；竖构图一致性好 | 缺下半身比例信息 | 平衡项，承上启下，提升构图自然度 |
| **全身立绘** | 学习身体比例、姿势、构图泛化 | 人脸像素过少，学不到面部细节 | 决定全身姿态泛化能力；缺失会导致全身崩坏 |

HuggingFace 官方训练博客（Diffusers 团队，最权威来源，huggingface.co/blog/sdxl_lora_advanced_script）的原话："特写照片对于最终产生真实感的效果很重要，但是同时也应该包含好的全身照片，以提高对不同姿势/构图的泛化能力。我们建议避免纳入离拍摄主体较远的照片，因为此类图像中的大多数像素与我们希望优化的概念无关。"反向失败案例（completeaitraining 课程）："只有特写自拍？全身图会很困难。只有侧脸？模型会过度生成侧面角度。"

**推荐配比（综合多来源）：**
- 个人博客 nick.txtcc.com《LoRA训练讲解》："全身:半身:局部特写 = 1:1:1，不宜高过 1:1:2"（对光环类角色可增加特写数量）。
- kohya_ss GitHub Discussion #2625 / Weird Wonderful AI Art 的 Flux Kontext 工作流："32 张头部特写(1:1)、24 张半身(4:3)、8 张全身(3:2)"，约 4:3:1（注：该原帖以"会提升相似度吗？"的设问提出，非已验证定论）。
- sanj.dev（2026）："人脸应占画面 40–60%"，数据集 15–30 张、20–25 最佳。
- 知乎《LoRA模型训练实测》：把数据集分 portrait/upper_body/full_body/bias 四个子文件夹，**给肖像文件夹更高 repeat 次数**——"拟合人物特征主要拟合面部……提高肖像文件夹 repeat 反而学得更快"。

实操建议：若只有一张高清全身图，可裁出"全身→七分身(cowboy shot)→半身→头肩→面部特写"多个景别，配合精准打标，也能凑出可用数据集（Civitai Dark_infinity 指南）。

### 二、训练集质量要素

**分辨率/像素：**
- SD1.5：512×512(1:1)、512×768(2:3)、768×512(3:2)；精细 LoRA 可 768×768。
- SDXL / Flux / SD3.5：1024×1024（或 1024×768）。
- 原图尽量 1024px 以上（低清可用 R-ESRGAN 4x+ / ESRGAN / LDSR 超分修复），分辨率须为 64 的倍数；开启 ARB Bucketing/分桶可免手动裁剪，混合横竖图。批量裁剪用 Birme（birme.net）。Flux 喜欢多分辨率列表 [512,768,1024]。

**背景处理（范式已变）：**
- 旧观念（仍适用于强调主体的场景）：纯色/简单背景、去背景（rembg），让模型学脸不学背景，"图片需凸显主体，不宜有复杂背景及文字"。
- 新主流（RunDiffusion 2025）："背景变化教会模型分离主体，而非记住固定环境……只要主体清晰可见，多样背景会增强 LoRA 灵活性。"
- 关键陷阱：纯黑/纯白背景会被模型"学进去"（kohya musubi-tuner issue #227 用户反馈黑背景"学太多"）。折中：背景多样但不喧宾夺主，必要时用蒙版训练(masked training)。

**光影质量：** 光照均匀、避免模糊/欠曝/过曝；多样光照（如 Rembrandt 光、不同时段）提升泛化。但训练集内若混入大量极端光影会干扰一致性，需平衡。

**角度多样性：** 正面、3/4 侧、纯侧面、背面，乃至俯视/仰视。SeaArt 指出某一角度若总搭配同一元素（如背面总配原服装），会导致"想要背面就出原服装"的耦合污染——任一维度最多用 3–6 张，角度可多用。

**色彩一致性 vs 多样性：** 遵循"训练目标一致、其余多样"原则。角色固有色（如发色、瞳色）应保持一致并通过删标绑定为触发词特征；而服装/场景配色应多样以防过拟合。风格 LoRA 则要求所有图风格统一。

**构图：** 主体清晰可辨、构图简单、避免杂乱元素和文字水印；单人优先，多人图会混淆。优先无损格式（PNG/TIFF）而非有损 JPEG。

**面部精修的重要性（人物 LoRA 命门）：** 真人 LoRA 对面部一致性要求极高，"真人形象比动漫角色各参数要求提高 20–70%"——真人单张 repeat 最好 >30、轮次 7–10，训练要集中面部主特征。常用 ADetailer/FaceDetailer 在出图阶段二次修脸（Impact Pack 的 FaceDetailer 隔离面部区域修复，对 1024 输出建议面部内部以 1536px+ 处理）。

**手部精修的必要性（相对低）：** ADetailer 的 Hand 模型"效果不太好"。社区主流不在训练集层面强求完美手部，而是出图后用 inpainting（去噪强度 0.25–0.4 修脸、0.5 修手）或专门手部 LoRA + ControlNet 修复。数据集层面只需保证手不严重遮挡面部即可。

### 三、单张/少量参考图扩充训练素材的主流方案

**工具代际与定位（从弱到强）：**

1. **Reference-only ControlNet**（最早）：能借参考图风格，但"无法有效利用参考图生成新视角，旋转到不同角度时服装等外观无法保持一致"（GitHub issue #2106）。仅适合轻度风格参考，不适合做多角度数据集。

2. **IP-Adapter / IP-Adapter-FaceID-Plus v2**：基于 CLIP/人脸嵌入迁移身份。FaceID-Plus 面部保真度较好但有"风格退化"问题，会把服装/光照/背景一并泄漏。适合快速换脸式扩充，需配 ControlNet 控姿势。

3. **InstantID（单图零训练）**：InstantID 论文（arXiv:2401.07519, Wang et al. 2024）将其定义为"a new state-of-the-art tuning-free method to achieve ID-Preserving generation with only a single image"——不训练 UNet、无需 test-time tuning，单张高质量正面脸即可跨 prompt 保持身份。但"身份精度略低于训练好的 LoRA"，且"对全身一致性弱、参考图有遮挡/低分辨率时身份漂移加剧"。适合先用它生成一批脸部一致的图，再训 LoRA。

4. **Flux Kontext（当前主力，推荐）**：Black Forest Labs 于 2025 年 5 月 29 日发布的上下文图像编辑模型；CEO Robin Rombach 在官方公告中称其"通过简单的 flow matching 训练，在多轮编辑中实现了 state-of-the-art 的角色一致性，同时保持 1MP 分辨率下 3–5 秒的交互式推理速度"（Black Forest Labs / Business Wire, 2025-05-29）。官方 KontextBench 评测显示"FLUX.1 Kontext [pro] 在全部六项 in-context 图像生成任务中持续位列最强，并在文本编辑和角色保持(Character Preservation)两项取得最高分"（bfl.ai/announcements/flux-1-kontext）。开源的 FLUX.1 Kontext [dev] 为 120 亿(12B)参数模型，官方称其在 KontextBench 人类偏好评测中"优于现有开源图像编辑模型(Bytedance Bagel, HiDream-E1-Full)和闭源模型(Google Gemini-Flash Image)"，并经 Artificial Analysis 独立评测确认（bfl.ai/announcements/flux-1-kontext-dev）。典型工作流：导入 1 张参考图 → 用 50 条 prompt 变体（不同姿势/服装/背景/表情）→ 批量生成 → 人工挑选 30+ 张 → FluxGym/AI-Toolkit 训练。Civitai 还有专门的 Flux Kontext Character Turnaround LoRA，单图直出"正面/侧面/3/4/背面"五视图转身表（作者 reverentelusarca，用 Ostris AI-Toolkit 训练）。

5. **Qwen-Image-Edit-2509 / 2511（与 Kontext 并列最强，身份一致性突出）**：阿里通义基于 200 亿(20B)参数 Qwen-Image 构建的图像编辑模型。官方 GitHub（QwenLM/Qwen-Image）说明 2509 版的关键改进为"Improved Person Editing Consistency: Better preservation of facial identity, supporting various portrait styles and pose transformations"，并新增多图输入（person+person/product/scene）支持——"即使表情/角度/光照变化也较少出现伪影或特征错配，是角色 LoRA 数据集的首选方案"。FloYo 工作流：上传 1 张脸 → 跑 20 条内置 prompt（左右侧脸、3/4、俯仰、Dutch tilt、Rembrandt 光）→ 自动写出图+caption。注意：该方案"专注头脸部，不适合全身角色表"，全身需另配管线。

**主流 ComfyUI 工作流推荐：**
- **RunComfy Consistent Character Creator 3.8**：基于 Qwen-Image-Edit-2511，一张参考图直出特写/转身/姿势/场景，含数据集导出工具（SaveImageTextDataSetToFolder）+ Florence2 自动打标。
- **FloYo: Flux Kontext Single Image to Character LoRA**：单图生成 60 张多姿势/光照/表情/环境变体，建议挑 30 张以上训练。
- **lovisdotio/workflow-comfyui-single-image-to-lora-flux**（GitHub）：Gemini 分析参考图 → 生成 20 条多样 prompt → Flux Kontext 生成 20 张一致变体的全自动流程。
- **Weird Wonderful AI Art 的 WWAA 自定义节点**（Flux Kontext 版 / Qwen 版）：附 50 条性别中性+女性 prompt 文件。
- **B站**：搜索"Kontext LoRA 训练保姆级教程""FLUX+Lora 自行生成一致人物数据集"，啦啦啦的小黄瓜、in-context-LoRA 等 UP 主有完整中文实操（含整合包与触发词）。

**Midjourney 方案（闭源补充）：** 据 Midjourney 官方文档（docs.midjourney.com/Omni-Reference），Character Reference（`--cref`）"兼容 Midjourney 和 Niji version 6"，配 `--cw 0–100` 控制角色一致性（cw 100 最强、含服装；cw 0 仅保留神韵）；V7 改用 Omni Reference（`--oref` + `--ow`，"可设 1 到 1,000 之间任意值，默认 --ow 100"），且"Omni Reference 只能与 version 7 配合使用"，`--cref` 与 V7 不兼容，严格角色一致仍常回退 V6。适合生成数据集种子图，但商用需注意版权与肖像权。

**"反向法"做编辑型 LoRA 数据对（Scenario）：** 训风格/编辑 LoRA 时，先准备好"目标(after)"图，再用 Kontext/Gemini 反向生成"输入(before)"图，保证配对完美对齐、风格一致。Kontext 训练需成对数据：输入图 _R / 输出图 _T（小志训练器）或特定命名对应（AI-Toolkit）。

### 四、训练参数速查（配合数据集）
- repeat × 图数 × epoch ÷ batch_size = 总步数；人物 LoRA 常需总步数 ≥1500–3000。
- Network dim/alpha：角色 SD1.5/SDXL 常用 dim 8–64、alpha 为 dim 的一半；Flux 角色 rank 16–64（128 细节多但易过拟合）。
- 学习率：1e-4 起步（真人面部可 4e-4）；优化器 AdamW/Prodigy；scheduler cosine/constant。
- Flux/SDXL 用自然语言长 caption；SD1.5/动漫用 Danbooru tag。删除"要绑定为角色固有特征"的标签（如发色），保留可调元素标签（姿势/表情/背景）。
- 监控：观察 loss（写实约 0.1–0.12）与中间 epoch 样图，样图与训练图趋同即停（过拟合）。

## Recommendations

**阶段一 · 准备锚定图（第1天）**：选/生成一张清晰正面、中性表情、无遮挡的**面部或胸像特写**作为身份锚点。若做真人，优先组织一次 20 分钟多角度补光拍摄，胜过 100 张随机社交照。

**阶段二 · 扩充数据集（首选路径）**：
- 有 GPU/会 ComfyUI → 用 **Flux Kontext 或 Qwen-Image-Edit-2509** 工作流，一图生成 45–60 张，按 **特写:半身:全身 ≈ 4:3:1 或 1:1:1** 挑选 25–40 张，人工剔除畸形/重复图。
- 只想快速试 → InstantID/IP-Adapter-FaceID 先出一批一致脸图。
- 闭源高质量种子 → Midjourney `--cref`(V6)/`--oref`(V7)。

**阶段三 · 预处理**：统一裁剪到底模原生分辨率（SDXL/Flux 1024，SD1.5 512–768），边为 64 倍数或开分桶；低清图超分；去水印；无损格式存储。背景保持多样但主体清晰，避免纯黑/纯白。

**阶段四 · 打标与训练**：触发词置 caption 首位；删除角色固有特征标签以绑定触发词；按 portrait/upper/full 分文件夹并给特写更高 repeat。用 FluxGym / AI-Toolkit / Kohya SD-Trainer（秋叶训练器）训练，每 1–2 epoch 存档。

**阶段五 · 出图修复**：用 ADetailer/FaceDetailer 修脸、inpainting 修手，而非在训练集上死磕手部。

**何时调整（阈值/基准）：**
- 全身出图崩坏 → 增补 3–5 张全身参考图重训。
- 出图与训练图雷同、发灰、做不出指定动作 → 过拟合，降 repeat/步数/dim，或推理时降 LoRA 权重至 0.5–0.6，加 200–500 张正则化图。
- 不像/触发词不生效 → 检查触发词与打标。
- 糊/少元素 → 检查数据集质量与分辨率。

## Caveats
- **配比数字非铁律**：1:1:1、4:3:1、人脸占 40–60%(一说 60–80%) 等来自不同来源（部分为个人博客/商业营销页/未经证实的 GitHub 假设帖），应作为起点而非定论，需按实测迭代。kohya_ss #2625 的"32:24:8"原帖本身是以"会提升相似度吗？"的设问形式提出，并非已验证结论。
- **背景处理两派并存**：去背景 vs 多样背景的最佳实践随底模演进而变化；Flux/SDXL 对背景分离能力更强，去背景的必要性下降，但具体仍取决于目标与底模。
