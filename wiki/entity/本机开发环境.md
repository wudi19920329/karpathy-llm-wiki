# 本机开发环境

## 摘要 / Summary

wudi 本机（Windows 11 专业版台式机）的硬件与运行时快照。在涉及"本机能不能跑 X"、"用哪个 Python"、"CUDA 版本"等问题时先查这里，免得重新 probe。

## 硬件

### CPU
- **AMD Ryzen 7 9700X** — 8核 / 16线程，基频 3.8 GHz
- L2 8 MB · L3 **32 MB**

### 内存
- **64 GB DDR5 双通道**（2× 32 GB Micron CP32G64C40U5B）
- JEDEC 5600 MT/s，**XMP 跑在 6400 MT/s**（已开超频）

### GPU

> [!important] RTX 5090 D v2 — 24 GB，非 32 GB
> 型号带 "D" 是中国定制版，显存从标准 5090 的 32 GB 削减至 **24 GB GDDR7**。
> CUDA Compute Capability **12.0**，驱动 596.49，nvidia-smi 实测显存 24455 MiB。

- 主: NVIDIA GeForce **RTX 5090 D v2**（24 GB GDDR7，CUDA 12.0）
- 辅: AMD Radeon(TM) Graphics（核显，2 GB，随 Ryzen 9000 系集成）
- 虚拟: OrayIddDriver（远程虚拟显示驱动，不影响 CUDA 工作负载）

### 磁盘
| 盘符 | 总容量 | 已用 | 可用 |
|------|--------|------|------|
| C | ~1907 GB | ~200 GB | ~1707 GB |
| D | ~1908 GB | ~636 GB | ~1272 GB |

### 操作系统
- Windows 11 专业版 64-bit · 版本 10.0.26200

## 运行时

### Python
| 项 | 值 |
|----|----|
| 版本 | **3.14.5**（2026 最新主版本） |
| 路径 | `C:\Users\admin\AppData\Local\Programs\Python\Python314\python.exe` |
| pip | 26.1.1 |
| uv | **0.11.24**（2026-06-23）— 替代 pip/venv/conda 的现代工具链 |
| conda | 未安装 |

- 无 conda / Anaconda；用 **uv** 管理虚拟环境和包。
- **uv 托管的解释器只有 3.14.5 一个**（即上面这个系统 Python）。`uv python list` 里其余版本（3.15.0b3、3.14.6、3.13.x、pypy、graalpy 等）都是 `<download available>` 未下载。虚拟环境是 per-project 的 `.venv`，uv 无「全局 venv 清单」——查某项目的环境需进该目录看 `.venv`。
- `python3` 命令映射到 WindowsApps shim；建议直接用 `python` 或全路径。
- 中文输出时需设 `PYTHONUTF8=1 PYTHONIOENCODING=utf-8`，见 [[Windows-Python-中文编码]]。

### Java
| 项 | 值 |
|----|----|
| JDK | **24.0.1** Oracle（build 24.0.1+9-30） |
| JDK 路径 | `C:\Program Files\Java\jdk-24` |
| Maven | **3.9.16**，路径 `D:\ProgramFiles\apache-maven-3.9.16` |
| Gradle | 未安装 |
| 默认编码 | UTF-8（Maven 显示 `platform encoding: UTF-8`） |

- JDK 24 是非-LTS 版本（LTS 为 21/25），日常开发兼容性需留意。
- Maven 装在 D 盘自定义路径，PATH 经 `C:\Program Files\Common Files\Oracle\Java\javapath` 暴露。

### Node.js
| 项 | 值 |
|----|----|
| Node | **v24.15.0** |
| npm | **11.14.1** |
| pnpm | 未安装 |
| yarn | 未安装 |
| nvm | 未安装（版本管理需手动或用 fnm/volta） |
| 全局 npm | `C:\Users\admin\AppData\Roaming\npm` |

- Node v24 属于当前 Active LTS 线（2026 年）。
- 无版本管理器；切换 Node 版本需手动安装或引入 fnm/volta。

### Go
| 项 | 值 |
|----|----|
| 版本 | **go1.26.4** windows/amd64 |
| go 路径 | `C:\Program Files\Go\bin\go.exe` |
| GOROOT | `C:\Program Files\Go` |
| GOPATH | `C:\Users\admin\go` |
| 模块缓存 | `C:\Users\admin\go\pkg\mod`（已有 github.com / golang.org / gopkg.in 等） |
| 构建缓存 | `C:\Users\admin\AppData\Local\go-build` |
| GOPROXY | `https://proxy.golang.org,direct`（默认国际代理） |
| GOTOOLCHAIN | `auto`（go.mod 要求更高版本时自动下载） |
| 已装工具 | `f2.exe` v2.2.2（[[F2-批量改名工具]]，ayoisaiah/f2 批量重命名 CLI，纯 Go，在 `GOPATH\bin`） |

- **PATH 已暴露两段**：`GOROOT\bin`（go 本体）+ `GOPATH\bin`（`go install` 的工具）→ 装完工具可直接命令行调用。
- go1.26.4 是 2026 年当前线；`GOTOOLCHAIN=auto` 意味着进某个要求更高 Go 版本的仓库时会自动拉对应工具链，无需手动管理多版本。

> [!warning] CGO 关闭 + 本机无 C 工具链 → 只能纯 Go 构建
> `CGO_ENABLED=0` 且 `gcc` / `clang` / `cmake` **均未安装**（见下方 [[本机开发环境#开发工具 / Dev tooling|开发工具]]段）。需要 cgo 的包（如 `mattn/go-sqlite3`、部分图像/音频绑定）**编译会失败**。要用得先装 C 工具链（mingw-w64 / TDM-GCC）**并**重开 `CGO_ENABLED=1`。

> [!note] GOPROXY 是国际代理而非国内镜像
> 当前 `GOPROXY=https://proxy.golang.org,direct`，国内网络拉模块可能慢/失败。需要时可切 `https://goproxy.cn,direct`（七牛镜像）。
